## 2. 完了済み作業（v3.3.0 + v3.3.1、全てユーザーテスト OK）

### v3.3.0（コミット fc4f402 + b1e4be9、push 済み）

**バグ**: BepInEx 5.4 の設定読み込みは C# エスケープを解釈する（`\\`→`\`、`\n`→改行）。cfg の `LastFolder` が単一バックスラッシュで書かれていると読込時に制御文字化し、`Path.IsPathRooted()` が Mono で **ArgumentException をスロー** → CatchUnityEventExceptions がコンポーネントを無効化 → ブラウザが開かない／開いても空の青ウィンドウで操作不能（OnGUI が毎フレーム同じ地点で例外中止）。

**修正**: TryRestoreLastFolder を try/catch + GetInvalidPathChars 事前チェックで防御化（不正値は警告 + 自己修復）/ Awake 全体を try/catch で保護（CatchUnityEventExceptions 対策として本番維持）/ [SB] デバッグログ全撤去。

### v3.3.1（コミット 48c631f「fix: rework modal blocking and config path handling (v3.3.1)」、ローカル）

v3.3.0 の EscapeConfigPath（保存時二重エスケープ）は**設計欠陥**だった: BepInEx のデコードはファイル読込時のみなので、同一セッション内ではメモリ上に四重バックスラッシュが残り、`Directory.Exists(四重パス)` が false → **設定 UI で追加したフォルダがツリーに出ない**（NAS フォルダ問題の原因）。さらにユーザーが削除ボタンで cfg を空にしていた。

1. **EscapeConfigPath 全面撤廃**: ファイルには二重バックスラッシュのまま保存（読込時 BepInEx が単一にデコード → 正規化ロジック :426-429 が二重に補正）。SettingsUi.cs Save*Folders 3箇所 / SceneBrowser.cs SelectFolder LastFolder / SceneExplorerPlugin.cs 正規化書き戻しから除去、ヘルパーメソッド削除
2. **モーダル制御の再設計**（ユーザー要件: ウィンドウ外は操作可能に・背後だけブロック）:
   - EventSystem ロック（uGUI 全体無効化）撤去
   - IMGUI 全画面クリック吸収レイヤー（GUI.depth=0 透明ボタン4枚）撤去
   - **透明 uGUI ブロックレイヤー追加**: Canvas（ScreenSpaceOverlay, sortingOrder 9999）+ Image + GraphicRaycaster。**Image は子 GameObject "BlockImage" に分離必須**（Canvas と同 GO に置くと Canvas の RectTransform が全画面固定されレイキャストが全画面になるバグあり。実機テストで発見）。`_blockRect.anchoredPosition = (x, Screen.height-(y+h))` で毎フレームウィンドウ矩形に追従。GUI.depth=-1000 と ResetClipLeak は維持
3. **設定 UI 刷新（designer）**: ファイルブラウザと同一デザイン（ヘッダー・配色・スタイル）、ウィンドウ幅をフォントサイズに連動（Mathf.Max(580f, fs*30f)）、説明文 7 行削除（README に誘導）、設定ウィンドウにも背後ブロックレイヤー追加（WindowId=981234、GUI.depth=-999、同名パターン）

### 検証済み事実（再調査を避けるため）

- CatchUnityEventExceptions.dll が Awake 例外でコンポーネントを無効化する仕組みは観測で確定
- BepInEx 5.4 の TimeStamps 設定はサポートされていない
- Unity 5.6 は OnGUI 例外を黙殺（output_log.txt に非表示）
- ScreenSpaceOverlay Canvas の RectTransform は Unity が全画面固定 → ブロック用 Image は必ず子 GO に置く
- cfg の手動編集はバックスラッシュ二重記述が正（単一 `\n` は制御文字化）。設定 UI からの入力はスラッシュ区切りで自動変換
