## 3. キャラブラウザ中止の記録（重要・再調査を避けるため）

### 経緯
1. v3.4.0 でメインゲーム（Koikatu.exe）のキャラロード/保存ダイアログをブラウザ化する対応を実装（fixer 委譲、SceneExplorerPlugin.cs +324/-1、SceneBrowser.cs +160/-21）
2. フック設計: `ChaCustom.CustomFileWindow.fwType`（UniRx ReactiveProperty）を Update から毎フレームポーリングし、CharaLoad/CharaSave 入遷移で標準パネル（objCharaLoad/objSave）を非表示にして SceneBrowser を表示。閉じる = btnClose.onClick.Invoke。fwType への書き込みは全面禁止（ping-pong 無限ループ防止）
3. ロード: `ChaFileControl.LoadFileLimited(path, (byte)(1-sex), true×5)` + `ChaControl.Reload(false×4)`。保存: `chaCtrl.chaFile.SaveCharaFile(path, unchecked((byte)-1), false)`（IL デコードでゲーム本体と同一引数を確認済み）
4. **ユーザーテストで失敗**: 「ファイルブラウザすらでてこない」（m0250）。LogOutput.log 調査: プラグインは正常ロード・全パッチ適用成功・Awake 正常だったが「メインゲームキャラロード開始」ログが一切なし = **DetectMainGameCharaLoad が発火していない**
5. **原因仮説（未確定・深掘りせず）**: キャラエディタのキャラロード UI の実体は `ChaCustom.CustomFileWindow` ではなく **`ChaFileListCtrl`**（exp-1 調査済み）の可能性が高く、fwType ポーリングが機能しない
6. ユーザー決定（m0250/m0257）: 「一旦キャラブラウザは中止」「コードはのこしておいて。スタジオとキャラクリどっちも衣装とキャラブラウザ無効で。シーンブラウザのみ有効状態で」

## 4. 検証済み事実（再調査を避けるため）

- CatchUnityEventExceptions.dll が Awake 例外でコンポーネントを無効化する仕組みは観測で確定（v3.3.0 で Awake try/catch 防御を本番維持）
- BepInEx 5.4 の設定読み込みは C# エスケープを解釈する（`\\`→`\`、`\n`→改行）。cfg 手動編集はバックスラッシュ二重記述が正
- BepInEx 5.4 の TimeStamps 設定はサポートされていない
- Unity 5.6 は OnGUI 例外を黙殺（output_log.txt に非表示）
- ScreenSpaceOverlay Canvas の RectTransform は Unity が全画面固定 → ウィンドウ追従ブロック用 Image は必ず子 GameObject に置く（全画面レイキャスト化バグを実機で発見済み）
- Koikatu と CharaStudio の Assembly-CSharp は同一ビルド（Studio 型はメインゲーム DLL にも同梱）。csproj はメインゲーム側 DLL 参照
- モーダル制御はウィンドウ矩形追従の透明 uGUI ブロックレイヤー（EventSystem ロック・全画面吸収レイヤーは v3.3.1 で撤去済み）。ウィンドウ外は操作可能・背後だけブロック
